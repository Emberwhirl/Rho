# Rho：把 R、项目工作区与 AI Agent 放进同一个桌面

做 R 分析时，我们常常在几个工具之间来回切换：在编辑器里写代码，在 Console 里看结果，在文件夹里寻找输出，再把报错、对象结构和代码片段复制给大模型。

模型或许能给出建议，但它通常不知道当前 R 会话里究竟有哪些对象，也不知道刚才运行的是哪一段代码。等建议回到编辑器，原本连续的分析现场已经被拆成了许多互不相连的碎片。

Rho 想解决的，正是这种割裂。

Rho 是一款面向 R 用户的 AI 桌面工作台。项目文件、代码编辑、实时 R 会话、分析结果和 AI 协作被放在同一个界面中。它不是简单地在编辑器旁边增加一个聊天框，而是让 AI 真正进入当前项目和分析现场。

目前，Rho 的 `0.2.0-dev.12` Windows 开发候选版已经具备一套完整的日常 R 分析工作流。

## 一个连续的 R 工作现场

打开 Rho 后，可以直接选择本地 R 项目。左侧是项目文件树，中间是多文档代码编辑器，下方集中显示 Console、Plots 和 Problems，右侧则是 Agent 与 Environment。

在编辑器中，可以运行选中的代码、当前行或整个文件。Console 中手动输入的命令、编辑器发起的执行，以及经过批准的 Agent 操作，最终都会进入同一个持续存在的 Workspace R 会话。

这意味着，刚刚创建的数据框、加载的包、生成的图和中间变量，不会因为切换交互入口而消失。Environment 展示的是这个真实会话中的对象，Agent 检查的也是同一份工作区状态。用户不必不断复制 `str()` 输出，也不需要反复向模型解释“我现在运行到了哪一步”。

项目状态同样会被保留。重新打开 Rho 时，应用可以恢复上次的项目、已打开文档、未保存草稿、光标位置和面板尺寸。外部文件发生变化时，Rho 会更新文件树，同时保护尚未保存的编辑内容，避免静默覆盖用户的工作。

## 从代码到结果，都留在一个工作台里

科学计算中的问题，往往不是“有没有输出”，而是“这个输出是怎样得到的”。

Rho 会保存每次代码运行的状态和结果。无论执行来自编辑器、Console 还是经过确认的 Agent 操作，都可以在 Runs 中找到对应记录。运行失败时，错误会进入 Problems 面板，并与相关代码和执行记录关联。

Agent 执行 R 代码后，输出、结果、消息、警告和错误会以清晰的形式呈现。用户可以直接判断代码做了什么、得到了什么，以及下一步是否需要调整。

绘图也不只是展示最后一张图片。Plots 提供当前会话和项目历史两个视图，并尽可能记录图像对应的 Run、源文件、文档版本和工作区修订。即使 Workspace R 或应用重启，已有的运行记录和问题线索仍然可以恢复。

对于 `.Rmd` 和 `.qmd` 文档，Rho 已支持受项目边界约束的渲染。未保存的文档会被阻止渲染；缺少 Quarto 或 R Markdown 工具、渲染失败等情况会作为结构化问题呈现，而不是只留下一段难以定位的终端输出。

## Agent 看得到现场，但不能越过用户

Rho 的 Agent 有三种模式：Ask、Plan 和 Act。

Ask 用于解释代码、对象和错误；Plan 用于整理下一步方案；两者都由底层策略强制保持只读。Act 可以提出执行 R 代码或修改项目文件，但“可以提出”不等于“可以直接动手”。

当 Agent 希望执行 R 代码时，Rho 会展示具体工具、完整代码和对应的工作区版本。只有用户明确批准后，这段代码才会进入 Workspace R。批准是一次性的，并与当时看到的参数和工作区修订绑定。如果分析现场已经变化，旧批准不能被拿来执行新的操作。

文件修改采用类似的审查流程。Agent 可以基于当前文件、当前选择或指定项目文件提出修改，界面会先展示 Before/After 差异。用户可以接受或拒绝；接受后，目标文件会重新打开并高亮修改位置，还可以在没有后续冲突时撤销。

Agent 可以理解当前编辑位置和项目文件，但修改是否真正写入项目，仍然由用户决定。这样既减少了来回复制代码的负担，也保留了对项目内容的控制。

## 选择适合自己的模型

Rho 可以配置多个模型提供商和多个模型，包括 OpenAI、Anthropic、Gemini、OpenAI-compatible 接口和本地兼容服务。模型选择器决定下一次 Agent 对话使用哪个模型，已经开始的任务不会被中途切换。

模型凭据从用户级 `.Renviron` 读取。管理界面可以检查配置状态并测试连接，项目之间不需要重复配置。

模型能力与操作权限也是分开的。只支持对话的模型仍可用于 Ask 和 Plan；只有确认支持工具调用的模型才能启用 Act。即使换成能力更强的模型，Workspace R 的执行审批和文件修改确认仍然有效。

## AI 与你使用同一个 R 工作区

很多 AI 编程工具只能读取用户粘贴进去的代码，却看不到当前 R 会话中的对象。Rho 的不同之处在于，编辑器、Console 和经过确认的 Agent 操作共享同一个 Workspace R。

当你刚刚创建一个数据框、加载一个包或生成一张图时，Agent 可以在授权范围内继续检查这个现场。它不需要另起一个与用户状态不同的 R 会话，也不要求用户反复整理上下文。

Rho 是本地桌面应用，运行 R 不依赖 Python、Jupyter Server 或 JupyterLab。已有的 R 项目、脚本和使用习惯可以继续保留。

## 出错时，尽量留下可以继续工作的界面

桌面软件的体验不只取决于顺利启动时有什么功能，也取决于依赖缺失时能否把问题说明白。

当前版本在找不到 R、R 版本低于 4.4，或 R 无法正常启动时，会保留恢复页面，允许重试、手动选择 `Rscript.exe`、复制诊断信息或打开日志目录，而不是直接退出。

如果 Agent 依赖或模型配置不可用，编辑器、Console、Environment 和 Plots 仍然可以使用，Agent 面板会单独显示不可用原因并提供重试。Quarto 等渲染工具同样属于可选能力，不会阻塞基础编辑与执行。

## 版本身份和更新检查

在当前主干中，Rho 已加入 `About Rho` 和 `Check for Updates...`。

About 界面可以显示应用版本、构建信息和运行环境摘要。遇到问题时，可以直接复制这些信息，方便定位具体版本。

更新检查会根据版本自动区分 stable 和 development channel。稳定版不会主动推荐预发布版本；开发版则可以发现较新的开发版本或稳定版本。更新失败属于可选网络能力，不会阻止 Rho、Workspace R 或项目启动。

当前版本可以发现新版本并打开 Rho 发布页面。安装仍由用户主动确认，应用不会在后台下载或自动运行安装程序。

## 一次典型工作流

以一个单细胞质控脚本为例，在 Rho 中可以这样完成一轮分析：

1. 打开项目，Rho 恢复文件、草稿和上次的界面状态；
2. 在代码编辑器中运行当前行、选区或完整脚本；
3. 在 Environment 中检查对象，在 Plots 中查看图，并在 Runs 中保留执行记录；
4. 遇到错误时，从 Problems 回到对应执行或源文件；
5. 用 Ask 让 Agent 结合当前项目和工作区解释问题；
6. 用 Plan 比较修正方案，再让 Act 提出具体代码或文件修改；
7. 检查准确的执行内容或 Before/After 差异，决定批准、拒绝或撤销；
8. 必要时重启 Workspace R，项目文件与审计记录仍然保留；
9. 在 About 中复制版本和诊断信息，或主动检查是否存在新版本。

这条路径的价值，不是少点击几次按钮，而是让代码、状态、结果、建议和决定始终留在同一个上下文里。

## 当前边界

Rho 目前仍是 Windows x64 的 `0.2.0-dev.12` 开发候选版，支持 Windows 10/11，需要 R 4.4 或更高版本以及 Microsoft Edge WebView2 Runtime。使用 Agent 功能还需要安装相关 R 依赖并配置可用模型。

当前版本已经完成核心功能和 Windows 安装包，但仍处于发布前验收阶段。安装包尚未完成正式签名，Windows SmartScreen 可能显示未知发布者提示。

目前暂不提供 macOS 和 Linux 安装包。更完整的 `renv` 操作、数据查看器、结果导出和远程计算也将在后续版本继续完善。

因此，现阶段更准确的说法是：Rho 已经具备可实际体验的 Windows 日常工作流，并进入了 release candidate 的质量与分发准备阶段。

## 写在最后

R 分析并不缺少编辑器、终端或聊天工具。真正稀缺的是一个连续、可恢复、可审查的工作现场：人知道 Agent 看到了什么，Agent 知道代码运行在什么状态上，而每一次改变都能回到具体的来源和决定。

Rho 正在沿着这个方向前进。

它希望保留 R 用户熟悉的项目、脚本和实时会话，同时让 AI 协作进入真正的分析上下文；它也希望在引入 Agent 能力时，不牺牲科学计算最需要的控制、边界与可追溯性。

这不是给 R 加一个聊天窗口，而是在重新组织人、代码、计算状态和 Agent 共同工作的方式。

如果你经常使用 R 完成数据分析，希望 AI 能理解当前项目和实时工作区，同时又不愿放弃对代码执行和文件修改的控制，Rho 会是一个值得尝试的新选择。
